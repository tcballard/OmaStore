# Local setup remixes

Select the components of a published setup, then choose **Remix this selection**. Required dependency references stay included. Desktop settings are an additional explicit selection; unselected local settings never enter the portable file. Save and rename personal versions under **Library → My setup remixes**.

The portable schema contains a local identity/version/name, exact parent ID/revision/creator, supplied sharing/media rights, selected public app/release references and supported setting choices. It contains no local inventory, observed configuration, paths, account identifiers or credentials. Unknown fields and unsafe/unknown setting values are rejected. Imports are bounded to 128 KiB. Reimporting the same record is harmless; another revision never silently overwrites an existing local save.

The native preview distinguishes the exact exported document from locally recomputed setting observations. Export checks that the reviewed digest still matches the save. On another machine, missing or changed releases and unavailable parent revisions stay visible differences. Selected application identities enter the existing installation planner and explicit confirmation flow. Desktop settings retain separate consent and recovery. Nothing runs on import.

A signed-in author can create a private submission draft from the selected portable document. This gives the remix a new public recipe identity, retains its parent attribution and uses the normal claim/media/check/review/publication flow. It does not publish. Existing maker support destinations remain the way to support curators; recipes remain free. Once complete parent attribution is set on a draft, editing cannot erase it. Preparation rechecks the exact published parent revision and any reused media rights.

Real Omarchy file-portal and customised-desktop evidence remains a release gate. Fixture media and sample theme names cannot establish real compatibility or author participation.
