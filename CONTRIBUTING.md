# Contributing

OmaStore is at the native-scaffold stage. Read `AGENTS.md` and the product specification before contributing.

Keep each change focused on one bundle. Describe the user-visible result, applicable acceptance criteria, checks performed and remaining limitations. A successful compile or structural check is not proof of Omarchy compatibility.

Use the Rust formatter and Clippy commands from the README. Build the Qt application and run CTest when its interface or process bridge changes. Include real Omarchy evidence when changing desktop integration or package execution.

App listings follow `SUBMISSION.md`; source-code contributions and application approval are different processes. Do not commit credentials, personal machine state, third-party media without publication rights or generated claims of verification.

New project code is contributed under the MIT licence. Preserve dependency notices and identify any different licence in the contribution.
