# Application submissions

The native Author workspace implements private drafts, real media uploads, exact preview, immutable submission, checks, independent review, revisions and publication status. A production intake deployment has not been supplied. The separate preview build provides fictional local sessions and a clearly labelled publication rehearsal.

1. Sign in through the system browser. Claim scoped project or domain control if you are the publisher; a community nomination remains unclaimed.
2. Describe the app, exact release/source or artifact, licence, distribution route, price, requirements and support. Upload media you have rights to publish. A draft and its edits stay private.
3. Inspect the exact preview and confirm public submission. This freezes one revision and queues a public GitHub issue when the product App is configured. Reviewer-only diagnostics and account data stay private. Later edits create another revision.
4. Respond to check findings and independent review. Compatibility evidence names the actual release bytes, environment, tester, date and limitations. Unavailable checks and an untested app never become a passing result. High-impact software requires two independent reviewers.
5. Request publication after approval. The native status distinguishes the issue, PR, merge and observed public catalogue. Maintainers review and merge the source PR; delivery is checked separately. Retry an ambiguous outcome through recovery, preserving its identifiers.

To start from a GitHub issue, use the application proposal template and include the native immutable revision marker as an exact line. Attach the issue number in the Author workspace; the worker validates the marker before reconciling it. This does not grant approval. Do not post private diagnostics, access tokens, customer data or proprietary source to the public issue.

To supply a direct catalogue PR, export the prepared exact files after publication preparation, write each UTF-8 file value verbatim to its stated repository path, supply the corresponding reviewed media, and attach the PR number. The external App verifies actual head bytes and current private approval. Extra files, changed receipts and edited contributor workflows cannot authorise a listing. See [operator setup and recovery](docs/PUBLICATION.md).

Authors may withdraw before delivery, revise findings and appeal a suspension. Public review history remains. Listing, normal review and updates are free. External sales and support links have no OmaStore fee; third-party provider fees may apply. Payment does not influence approval, ranking or editorial selection. Managed commerce remains a separately gated bundle.
